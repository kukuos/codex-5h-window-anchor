# Codex 5 小时额度窗口锚点（Codex 5h Window Anchor）

让 Codex 的 5 小时额度窗口在**你选的整点**开始，而不是在你随手发出第一条请求的那一刻开始。

**简体中文** | [English](README.en.md)

## 问题是什么

Codex（ChatGPT 订阅）的额度窗口是滚动的：从当前窗口的**第一条请求**起算 5 小时后重置。实际后果是，你上午 11:23 才开始用，窗口就是 11:23–16:23、16:23–21:23……重置点全天漂移，很容易在你正忙的时候撞上限流。

## 方案

在窗口空闲时段，每天固定时间自动发一条**极简请求**，让它成为新窗口的第一条：

| 锚点（Asia/Taipei） | 锚定的窗口 | 重置时间 |
|---|---|---|
| 08:00 | 08:00–13:00 | 13:00 |
| 13:00 | 13:00–18:00 | 18:00 |
| 18:00 | 18:00–23:00 | 23:00 |
| 22:00 | 22:00–次日 03:00（或接住漂移的窗口） | 次日 03:00 |

窗口已在运行的锚点只是落在窗口内、无副作用；窗口已结束的锚点负责把新窗口锚回整点。多个锚点互为容错：白天窗口因实际使用漂移了，晚上的锚点还能接得住。

每条锚点请求固定为最省的组合（实测每次 **1,941 tokens**）：

```bash
mkdir -p /tmp/codex-ping && cd /tmp/codex-ping && timeout 180 codex exec \
  --ephemeral --skip-git-repo-check -s read-only \
  -m gpt-6-luna -c model_reasoning_effort="low" \
  "Say OK only" < /dev/null
```

关键细节（都是实测踩过的）：

- **必须带 `< /dev/null`**，否则 `codex exec` 会等待 stdin 而挂起。
- **不要用管道**接这条命令，管道会掩盖真实退出码。
- 提示词本身只占十几个字符；一次 Codex 请求的固定开销（系统指令、工具定义，实测量约 5.9 万字符）才是大头。所以省额度的关键是**模型档位**：用最轻的 Luna + 最低推理档，而不是缩短提示词。
- 不适用于 API Key 按量计费：那种计费没有 5 小时窗口。

## 怎么用（给 Muse 用户）

1. 打开 [PROMPT.md](PROMPT.md)，复制里面的提示词全文。
2. 按需改开头的参数（锚点时间、时区、报告方式）。
3. 粘贴到你的 Muse 对话里，剩下的事 Muse 会做完：在本机登录 Codex（设备码授权）、验证链路、建好 4 个每日定时任务，并汇总下次运行时间。
4. 成功静默、失败才报告，平时不用管它。

## 前置条件

- 一个能定时运行任务的 Muse，且 Codex CLI 装在同一台机器上
- ChatGPT 订阅账号（Plus / Pro 等，凡是有 Codex 5 小时窗口的套餐）

## 实测记录

方案于 2026-10-27 搭建、验证，之后按计划运行：2026-10-27 的 18:00、22:00 和 2026-10-28 的 08:00 锚点均成功，每次消耗 1,941 tokens，窗口重置时间与锚点时间对齐。

搭建当天还有一个附带验证：额度已被用完时试发请求，Codex 返回的限流提示时间与账号实际重置时间完全一致——证明锚点请求打到的是同一个账号、同一套额度。
